# SPEC · the extractor: a person's typed messages, out of a session record

**Ground truth.** A Claude Code session record is a file of events, one JSON object per line. Measured on the owner's recent session records, structure only, no content read (a later such read looks only at this build's own records, his ruling): every `user` and `assistant` event carries `type` and `timestamp` (ISO 8601 UTC with milliseconds, ending `Z`; events of the harness's own bookkeeping types carry no timestamp and are never read); a `user` event carries `message.role` (`user` in every one seen) and `message.content` as a plain string or as a list of parts, each with a `type` (`text`, `tool_result`, `image` were seen); some `user` events carry `isMeta: true` and are the harness's, not the person's; recent events carry `promptSource` (`typed`, `queued`, `system`, `sdk` seen), older ones do not; a typed string can hold blocks the harness inserted, wrapped in named tags, and one string in forty records was a bare bracketed marker. Measured in this build's own folder (four records, structure only): an `assistant` event's `message.content` is always a list of parts, one part per event, of type `text`, `thinking` or `tool_use`. The owner pulled his quoted lines out of real records by hand and ruled five inputs (below). The checker ([SPEC-your-words.md](SPEC-your-words.md)) takes plain text; this tool writes that shape from a record. The owner's real records stay private: every fixture here is a synthetic session.

**In.** `tools/your-words/extract.py`, the second half of the your-words tool: read one or more records, keep only what the person typed, write the checker's plain-text shape, report with times, log the run. **Out.** Any other record format; reading a curated words file as a source (the owner's ruling: one had silently corrected a misspelling he typed; the record is the only source). **Deferred.** Nothing: the counts below are the whole of what it reports.

## What counts as typed (the owner's rulings, each a rule here)

- **Only what the person typed.** *Why:* a paste, a tool's result and the harness's own text are not the person's words, and a checker fed them would call a misquote exact. Only `user` events yield typed text; `assistant` events are read for their `text` parts alone, to count the words quoted back (below); every other event type is skipped and counted by type. A `user` event is skipped as *harness* when `isMeta` is true, or when `promptSource` is present and is neither `typed` nor `queued` (a `promptSource` that is not a string is can't read); a `user` event whose `message.role` is missing or not `user` is can't read. From a string, take the string; from a list, take the `text` of every part whose `type` is `text`, joined in order with nothing between; every other part (`tool_result`, `image`, any other) is skipped and counted by its type name. Then remove every harness block: from an opening tag that stands at the start of a line (white space before it allowed) or carries an attribute (`<name` followed by a space or `>`, attributes and all; names match letter for letter, lower case) to the first closing tag of that name after it that carries the opening tag's id, when the opening tag has one (`</name id="…">`: a real record repeats a paste's id in its closing tag); when the opening tag has no id, to the first closing tag of that name, bare (`</name>`) or carrying attributes (a closing tag with another id, or with none, inside a block whose opening tag has an id is part of the body; a block whose matching closing tag never comes is left as typed), for the names in the tool's table: `pasted_content` (a paste is not typing), `system-reminder`, `command-name`, `command-message`, `command-args`, `local-command-stdout`, `local-command-stderr`, `local-command-caveat`, `task-notification`, `teammate-message`, `bash-input`, `bash-stdout`, `bash-stderr`; and remove a line that begins with the marker `[Request interrupted` (the table's one marker prefix; no other bracketed line is touched). A tag typed mid-line with no attribute, or with no closing tag, is left as typed (a person may type a tag's name in prose); a block typed at a line's start with its closing tag is removed, and the header says so, as it says that words a person types as a command or its arguments go with the command. After a removal, a line left empty, or holding only white space, where the block stood is dropped and nothing else changes (a block inside a line leaves the text either side as it stands). The table is hand-kept; a tag or marker outside it, a short paste the harness did not tag, a prompt an agent wrote into a seat's own record, and a summary the harness wrote after compaction, each pass as typed, and the header says so. What remains, if it holds any non-white-space character, is one typed message; otherwise the event is counted as *nothing typed*.
- **White space is kept exactly**, double spaces and line breaks included; nothing is corrected, trimmed or re-wrapped (*why:* the checker's *corrected* outcome exists to name exactly these differences, so the source must still hold them). One exception: blank lines at the start or end of a message are dropped, because the output shape cannot hold them, and the report counts each time it did so. A blank line *inside* a message stays, and the checker then reads that message as two blocks (its rule); the report counts these too.
- **The origin is the earliest typed occurrence, and the report says how many later occurrences exist.** Messages are ordered by `timestamp` parsed as a UTC date (a timestamp of another shape, or without a zone, is a can't-read event), never compared as text, across every record given (records are numbered in the order given; two events at one instant keep record order, then line order, and the report names the tie). A later typed message whose text, after the removals above, equals an earlier one's, character for character, is not written and is counted as a later occurrence *typed*; the origin's report line lists its times. Each message's exact text is also counted where it recurs *inside* later material: a later typed message that holds it inside new words (kept whole as a message of its own, counted under *typed*; the checker may then match a quote to that later message when it reads exact there, as it would a re-sent correction: a named limit, not a defect), a removed `pasted_content` block (no other removed block counts), and the `text` parts of later `assistant` events (the words quoted back). A recurrence is the exact text of a whole message with nothing but a non-word character, or the text's edge, on either side, a word character being any letter or digit of any script or an apostrophe (so *no* inside *know*, *can* inside *can't* and *v2* inside *v21* are none), counted once per later message, paste or quote-back; a span quoted back from inside a message is not counted, and the header says so. The counts are per origin: `later: k (typed n · pasted n · quoted back n)`.
- **The record is the only source.** The input is a record; the output is a words file; the tool never reads one as the other.
- **Both shapes have a fixture**: a typed string and a list of text parts, each keeping a double space and a misspelling.

## Output, report, exit

- `python3 tools/your-words/extract.py <record.jsonl> [more] --out <file> [--times <file>]` writes the typed messages, each as a block of lines, blocks separated by one blank line, nothing else, UTF-8 (the checker's input shape: a quote is found inside a message, so whole messages serve). `--out` is required; `--times` writes one line per block as the checker counts blocks (a message with an inner blank line gives two lines with one time), `block n · <timestamp as recorded> · <record>:<line> · later: k (…)`. Either path is refused (exit 2), with the reason and nothing written, when a file exists there, when its folder does not exist, or when its folder lies inside the repository that holds the tool, judged by folder identity and by git's own answer for that folder's top level, never by path text (links, letter case and a volume's alias all hide a path inside): extracted text is a person's private material and never lands in the public tree (fixtures' expected outputs are fixtures, not `--out` targets). A record outside that repository is named in rows and reports as *outside the repository (record n)*, numbered in the order given, never by path (a path into a person's machine is private), and every count about it is a count, never text.
- **Report** (standard output): one line per typed message, `n · <timestamp> · <the first eight words>… · later: k (typed n · pasted n · quoted back n) at <the later timestamps as recorded, comma-separated>`; then `messages: n · later occurrences: n · nothing typed: n · harness events skipped: n · other events skipped: <type n, …> · parts skipped: <type n, …>` (types in name order) ` · edge blank lines dropped: n · inner blank lines kept: n · blocks left whole: n · can't read: n` (a block left whole is an opening tag that would have opened a block, with no closing tag that matches: it stays in the output, in sight, and is counted here so a reader need not search for it), then what was read and what could not be seen, never *clean* for a record it could not read. **Exit** 0 when every line was read and at least one message was written; 2, with *can't read* on each such line, when any line or `user` event could not be read (not JSON; a leading byte-order mark is accepted; no `timestamp` or `type`; a `user` event with no `message.content` in either shape, a bad `role`, or a part without `type`; an unreadable or non-UTF-8 file), the readable rest still written and the unreadable counted; 2 also when no typed message was found (the twin: can't read rather than red, because the material is empty, not faulty; a check's twin is red because a check that finds nothing is blind to the repository it guards); never 1: the extractor produces, it catches nothing, and its `caught` is always empty (said in the header).
- **Run log** ([SPEC-run-log.md](SPEC-run-log.md)): one `real` row per person's run under the tool id `your-words` (the owner's ruling names the checker and the extractor as two halves of one tool; one card and one log id is this session's reading of it); `read` the records (relative paths, or the phrase above), `compared_against` empty, `outcomes` the counts above as `messages`, `later`, `nothing_typed`, `harness_skipped`, `events_skipped`, `parts_skipped`, `edge_blank_dropped`, `inner_blank_kept`, `blocks_left_whole`, `cant_read` (each a whole number; `later` the total), `caught` empty, `could_not` one line per unreadable line as `<record>:<line>` or a count for an outside record; `--planted "<what, by whom>"` and `--no-log` as the checker. The card's sentence counts the checker's runs and the extractor's runs apart, telling them by the outcome names each half writes ([SPEC-card.md](SPEC-card.md)), so *n real runs, nothing caught yet* never counts runs that could not catch.
- **Header:** how it is fired, and the failure that earned it: a curated words file that had silently corrected a misspelling the person typed, read as if it were the source.

## Self-test (`--selftest`, fixtures in `tools/your-words/tests/extract/`, synthetic sessions only)

String and list shapes · a tag with attributes around a paste inside a typed line (the line kept, the block gone), and a paste on its own lines (its emptied line dropped) · a tag's name typed as prose (kept) · the same words inside a longer word (not a recurrence) · a tool-result-only event (nothing typed) · an `isMeta` event and a `promptSource: system` event (harness, counted) · a bracketed marker line · a slash-command event (nothing typed after removal) · the same words typed at two times (the earliest kept, one later typed, its time listed) · the same words inside a later paste and inside a later `assistant` text (pasted 1, quoted back 1) · events out of time order, one pair differing only in milliseconds (ordered as dates) · two records with the same message at one instant (record order, named) · a line that is not JSON (counted, the rest written, exit 2) · a `user` event with no `message.content`, and one with `role` missing (each can't read) · a record with no typed message (the twin, exit 2) · an existing `--out` file, and an `--out` inside the repository given by a link, in another letter case and by the volume's alias (each refused) · a prose tag followed by a real block of the same name (the prose kept) · a timestamp without a zone (can't read) · a message with an inner blank line (kept, counted) · the extracted output of the string fixture fed to the checker (`--no-log`) against a fixture page quoting it: exact. Prints fixture text only; writes exactly one `planted` row; exits 0 only when every fixture gives its expected outcome.

## Done when

- The self-test passes; a reviewer's own synthetic record, with a plant of each kind (a paste holding the typed words, a quoted-back later occurrence, a tag with attributes from the table, a misspelling and a double space), extracts to exactly the typed text, counts the rest, and leaves a planted row.
- **The owner's private act, after the lane:** he runs it on the records his intent and learning were quoted from, and runs the checker against that output; both rows land in this repository's log with no path and no text, and the build log carries the counts (the act most likely to catch something real: it tests the sessions' transcriptions against the only source his ruling trusts).
- It runs in the fresh container of the checker's done-when, from a clone, on the fixtures.
