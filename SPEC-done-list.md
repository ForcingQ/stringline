# SPEC · the done-list checker: a Claude Code hook with its own tests

**Ground truth.** The owner opens every session and every lane with a finished list: numbered items, each tagged by how it is proven. The checker he uses privately runs the items' commands and, as a hook on the end of an agent's turn, keeps a lane going while items are still open. Its two founding instances are in this record: a list written in a shape its own checker could not read, and a line that passed before any work (the founding, wrong turn 1; the second session, wrong turn 1: one catch by the tool, the other by the person who read a pass). In his practice the hook has been seen to fire only when the agent session runs in its own terminal, never inside a background seat. It is the runner-up tool ([DECISIONS.md](DECISIONS.md) #16), built fresh from this page.

**In.** `tools/done-list/done_list.py` with a card, a run log and fixtures: `check`, `hook`, `report`. **Out.** Judging a YOURS or WITNESSED item (a person's words close them; the tool sees only that a file exists); any model call; subagent stops (named below). **Deferred.** A step that arms the hook from inside a session; here the hook is armed by configuration.

## The list

One block in a markdown file between `<!-- done-list root="<folder the checks run in>" cap=3 timeout=60 -->` and `<!-- /done-list -->`; `root` is optional and defaults to the folder holding the file, a relative root is read from that folder (a committed list names no machine path); the attributes are `key=value` pairs, a value in double quotes when it holds a space; `cap` is the most automatic continuations in a row (3 at most; a larger value is read as 3 and said; absent means 3; below 1 or not a whole number is MALFORMED), `timeout` the whole seconds per check (absent means 60; not a whole number is MALFORMED). A check command runs through `sh -c` from the root; text may follow the closing backtick (a note on what the command proves) and is not part of the command. Inside the block every non-blank line is an item, a RESCOPE line, or MALFORMED. An item is one line, `n. **TAG** — <what is true> · <proof>` (the number, a full stop, the bold tag), with TAG one of the five below (any other word is MALFORMED; numbers need not run in order): **POINTABLE** (`check:` a command in backticks: the text between the first backtick after `check:` and the last backtick on the line, so a note after the command holds no code span; a command holding a backtick is MALFORMED, `$(…)` serves for nesting; exit 0 means done; that it is read-only is the author's word, the tool runs what the list holds, and a list is trusted only from a tree the person controls), **YOURS** (`words:` the path where the person's words land; *present* means a file there with at least one non-blank line), **WITNESSED** (`seen by:` who looks · `evidence:` the path of the record of the seeing), **CONDITIONAL** (`depends on:` · `see it by:`), **UNSORTED** (plain words). A POINTABLE may carry `[before-work ok]` anywhere in its text outside the command when it is meant to pass before the work (a recording that is the first act). A `- RESCOPE <date>: …` line inside the block records a change and is never an item. *Why tags by proof:* an item is closed by the kind of evidence it names, and a script may close only the first kind.

## `check <list>`: one line per item, three states

`#n DONE` (exit 0) · `#n NOT DONE (exit k)` · `#n CAN'T TELL (<why>)` when the command could not start (exit 126 or 127) or timed out (the command's whole process group ended) · `#n MALFORMED (<why>)` for a line that is not an item (a bullet, a bracket after the number, a leading space, prose), a POINTABLE with no command or with a backtick inside it, a repeated item number · `#n YOURS · words at <path>: present|absent` · `#n WITNESSED · evidence present|absent` · `#n CONDITIONAL` and `#n UNSORTED` as written. Then `pointable: done n · not done n · can't tell n · malformed n`, what was read and what could not be seen. Exit 1 if any NOT DONE or MALFORMED (a malformed line is a fault in the list, the founding catch), else 2 if any CAN'T TELL, else 0. A file with no block, with two blocks, or a block that does not close or holds no item is can't tell (exit 2) for `check`: it is not a list. `--before-work`: the same run, and every POINTABLE already DONE without `[before-work ok]` is a catch, *passes before the work*; exit 1 when any. **Run log** ([SPEC-run-log.md](SPEC-run-log.md)): a person's `check` writes one `real` row under `done-list`: `read` the list file and `compared_against` its root (a path outside the repository is written as *outside the repository*, never by path), `outcomes` the counts, `caught` each malformed line and each pass before the work as an item number, or `line n` for a line with none (never the line's text), `could_not` each can't tell by item number; `--planted` and `--no-log` as the checker. `report` writes no row.

## `hook`: the Stop hook, armed by configuration

- **Fired by** a `Stop` hook of type `command` in a project's `.claude/settings.json` (or its local, ignored one): the entry `{"hooks": {"Stop": [{"hooks": [{"type": "command", "command": "python3 <abs>/tools/done-list/done_list.py hook --list <abs list>", "timeout": <seconds>}]}]}}`, the `timeout` set above one run of the list's checks (the sum of their timeouts: each fire runs them once). Nothing in this repository installs it (a hook in every agent's session here would be an act of the owner's); `--help` prints that entry. It reads the hook's JSON on standard input: `hook_event_name`, `session_id`, `stop_hook_active`, `transcript_path`, and `last_assistant_message` when present. **Only `Stop` is acted on, and only `Stop` touches the counter:** the entry arms `Stop`, and the hook also refuses to act on any other event it is handed (a misconfigured entry cannot block a subagent), because the lane this serves runs in its own terminal and the hook has not been seen to reach a background seat.
- **Writes two log lines per fire:** `fired`, before anything else, and `acted` with the action and the open items, so a hook the harness kills mid-run leaves a `fired` line with no `acted` line, which `report` counts as a killed fire. **Allows the stop** (exit 0, nothing printed) when: the last assistant message, from `last_assistant_message` or else from the transcript at `transcript_path` (the last `assistant` event holding a `text` part that comes after the last `user` event, so a stop line from an earlier turn is never read), ends with `STOP: YOURS #n` or `STOP: BLOCKED #n: …` as its last non-blank line, written plain (trailing white space, backticks and a closing code fence ignored; no bold; the YOURS form ends with the number, the BLOCKED form's reason may end with a full stop; a declared stop is never overridden; a YOURS claim on an item not tagged YOURS or WITNESSED, or on a number no item has, is logged; a BLOCKED claim is never checked; **every stop line is the lane's own and can be forged**, so the log, not the hook, is what a reader of the lane trusts) · every POINTABLE check exits 0 and no line is MALFORMED (a malformed line, and a file that opens but is not a list, are open items for the hook as for `check`: the founding failure must not let a lane stop, and the cap bounds how long it blocks) · the cap is reached · the list file cannot be opened at all, (an `assistant` event's content is a list of parts, `text`, `thinking` or `tool_use`, one per event, measured in this build's own folder; a turn whose assistant events hold no `text` has declared no stop, and the checks decide) · the input is not JSON, or the hook itself errs (fail-open: a hook that blocks on its own error traps the session; every such allow is logged with the error, and when the log itself cannot be written the error goes to standard error).
- **Otherwise blocks:** prints `{"decision": "block", "reason": "…"}` on standard output and exits 0, the reason naming each open item with its state, *continuation k of cap*, and the two stop lines; on the last continuation, that open items are to be written as NOT DONE and the lane to stop. The count of consecutive blocks is the tool's own, kept per session in `<state>/<session_id>.json` as `{"blocks": k}`, reset at every allow, so a killed session leaves the next one starting at zero; `stop_hook_active` is recorded in the log and never relied on (it says a hook already continued, not how often). **A hook run writes no row** (it fires at every turn end, in a session where nothing commits); its record is `<state>/log.jsonl`, JSON lines with the keys `time`, `session_id`, `event`, `step` (`fired` or `acted`), `action`, `open` (item numbers), `stop_hook_active`, `note`, where `<state>` is `.done-list/` beside the list (the lane adds `.done-list/` to this repository's `.gitignore`; a person adds it to their own) or the folder given with `--state <dir>` (the self-test's scratch). `report <list>` prints that log as lines a lane's report can carry: `fires: n · killed: n · continuations: n · cap hits: n · declared stops: n · allowed on error: n`, or *hook never fired: can't tell* when the log is empty.
- **Header:** how it is fired, the failure that earned it (a list its own checker could not read; a line that passed before the work), and what it does not prove: that a check measures the work, that a YOURS stop was honoured, that the hook reaches a background seat.

## Self-test (`--selftest`, fixtures in `tools/done-list/tests/`) and done when

Fixtures (lists with no `root`, or a relative one, so they run anywhere): a list with all five tags and one of each `check` state · a malformed line · a line passing before work, and one marked `[before-work ok]` (`--before-work` catches the first only) · a command that cannot start · one that times out (`timeout=1`) · a file with no block, and one with two (twin, can't tell) · hook inputs, piped as JSON to the script with `--state` in scratch, never through the harness: a `Stop` whose message ends `STOP: YOURS #2` (allow) · the same stop line with a trailing backtick (allow) · open items (block; the JSON parsed back) · three blocks then the cap (allow; the counter reset at an allow) · `last_assistant_message` absent and a synthetic transcript's last `assistant` event read instead · a `STOP: YOURS` on a POINTABLE item and one on a number no item has (allow, logged) · a stop line followed by a closing fence (allow) · a malformed list (block, naming the line) · a turn whose assistant events hold no text, after an earlier turn's stop line (the stale line not read; block on open items) · a nested backtick in a command, and a code span in a note (each MALFORMED) · an unwritable state folder (allow, the error on standard error) · a file that opens but is not a list (block, naming why) · a `SubagentStop` (allow, logged) · stdin that is not JSON (allow, logged) · a list the hook cannot read (allow, logged). Prints fixture text only; writes exactly one `planted` row and leaves nothing else under the tree. **Done when:** the self-test passes; a reviewer plants a list of its own with a passing-before-work line, a malformed line and a forged stop line that is not the last line, and the tool names each as the spec says; a person's `check` on a fixture list with the plant flag leaves a planted row carrying the note; the card exists at `building` and reads *no real run yet* until the owner runs it, privately, on a copy of one finished list from a build lane (a lane is one agent session with its own list, [MAP.md](MAP.md)) with only its two marker lines changed to this tool's (his own lists use another instrument's marker, which public code never names; the build log says the copy was re-marked), the row carrying item numbers and counts only; the hook, installed by hand in a scratch project's local settings and driven by a live agent session there, blocks once and allows on a declared stop (the one proof that cannot run in the workflow, recorded in the lane's reports with the log lines).
