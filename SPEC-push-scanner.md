# SPEC · the push scanner: public code, private list

**Ground truth.** The check that keeps private words out of this repository exists and runs: a local pre-push hook calls a scanner that reads everything git sends on a push and refuses on any hit, proven on 14 planted words and 2 clean controls before the first real push and re-proven at every open. Its code and its word list live in the private folder, so a stranger sees the claim and not the mechanism. The owner's ruling: the scanner becomes public code, rebuilt from its proven design with invented plants; the word list stays private. It replaces the "public copy" the guard spec first described as its check 5.

**In.** `checks/push_scan.py`, a sample word list `checks/push-scan.sample.txt`, a sample hook `checks/hook-pre-push.sample`, fixtures, a self-test. **Out.** The owner's word list, which never crosses; the owner's own hook, which keeps guarding this repository as it is; a card or a log (it is a check, not a tool: [DECISIONS.md](DECISIONS.md) #37; the sample hook shows how the mechanism installs for a person's own repository, and whether it becomes a tool with a card is the owner's call). **Deferred.** Running the public code behind the owner's own hook (his call, once its self-test has run here).

## What it reads, and how

- **Modes.** In every mode a file's path name is scanned as well as its content. `--files F…` scans files; `--stdin` scans text (a commit message); `--tree` scans every tracked path name and file and the current commit's raw object (author, committer, message): this is check 5 in `run_all.py`, and in this mode alone it prints the guard's one line, `GREEN · read <n> files, <m> binary counted, 1 commit · against <list> · skipped <the MANIFEST's files>`, `RED: <n> hit(s), first <where>:<line>: [<term>]` or `CAN'T TELL: <why>` ([SPEC-guard.md](SPEC-guard.md)); `--history <repo>` scans every commit reachable from any ref (raw object, every path, every file) and every tag object; `--prepush` reads the lines git gives a pre-push hook on standard input, `<local ref> <local id> <remote ref> <remote id>`, and for each pushed ref scans the pushed object (a tag is scanned, then followed to its commit) and every commit the remote lacks (a new ref: every commit it reaches; an update: the commits between the remote's id and the local one), each commit's raw object, path names and files, each file read once; a line whose local id is all zeros is a deletion, pushes no content, and is counted, not scanned, so a push of deletions alone is CLEAN, saying so (git runs the hook with nothing when nothing is pushed; the twin below is `--tree`'s alone); `--list <path>` names another word list (default: the sample). Each pushed commit's whole tree is scanned (every file by its content id, read once), not the commit's changes alone, which is how a word that arrives only in a merge's resolution is seen; a remote id the local repository does not hold (a fetch gap) is can't tell. In every mode but `--tree`, the output is every hit as `<where>:<line>: [<term>]` (a hit in a path name as `<path> <name>:0`), then one summary line, `CLEAN`, `<n> HIT(S)` or `CAN'T TELL (<why>)`, each naming what was read (one term for the blind state across the guard: *can't tell*). `--selftest` below.
- **Matching.** A list line is a word or phrase (spaces inside it match literally), matched without regard to case; a line opening `w:` matches only where a non-word character or the text's edge stands on both sides (a word character is a letter or digit after folding; a phrase may carry `w:` too); `#` lines are comments; an empty list is a refusal (can't tell). Before matching, text is folded, in this order: Unicode compatibility normalisation (NFKC: full-width forms, superscripts), removal of invisible format characters (Unicode's *format* category: zero-width spaces and joiners, soft hyphens), **the look-alike table** (hand-kept by the lane, at least these entries: the Cyrillic letters that resemble Latin a, c, e, o, p, x, y, each to its Latin look-alike; the digits 0, 1, 3, 5 to o, l, e, s; small by design, so a disguise outside it passes, and the header says so), then lower case; the near-miss controls use no character the table folds. Line numbers in hits are the file's own; in `<path> <name>:0`, `<path>` is the path and `<name>` the literal word *name*. **What is read as text:** a file with a text extension (`.md .txt .toml .py .yml .yaml .json .html .sample`) is decoded as UTF-8, and also as UTF-16 in both byte orders when it carries a mark or NUL bytes, every successful reading scanned; whenever the UTF-8 reading fails, for any file read as text whatever its extension and whatever a UTF-16 reading gave, it is also read as UTF-8 with replacement and as Latin-1, both readings scanned, and counted in the line as *read with replacement*, never can't tell (the owner's two rulings of 8 October: five pushed commits held a fixture that decodes no way and history is never rewritten; then a Latin-1 file with a stray NUL at an even length had read as UTF-16 nonsense and passed). Any other file is decoded as UTF-16 when it carries a UTF-16 mark, else read as UTF-8 with replacement when it holds no NUL byte in its first 8,000 bytes (git's own rule), else counted by name as binary and not scanned, the count in the line (an unmarked UTF-16 file without a text extension is therefore not seen, a named limit). A path given to `--files` is scanned as given. A symbolic link is scanned by its target's path text and never followed; a submodule is counted by name and not scanned. The header says each of these. *Why these:* each is a way a planted word slipped past the first private version ([the founding's entry](BUILD-LOG-2026-10-07-s1-the-founding.md), wrong turn 3). What it does not see, in its header: a word split across lines or spelled with spaces, a word inside a compressed, encrypted or binary file, inside a submodule, or behind a link, and a disguise outside those foldings and outside the look-alike table.
- **Three states.** Exit 0 when nothing hit; exit 1 when any did, even when something else could not be read (a hit is known; the can't-look is printed beside it); exit 1 also for the twin, `--tree` that decoded zero files as text (a check that finds nothing to read is blind to the repository it guards, red by the binding rule); exit 2 when nothing hit and input could not be read, `--files` was given no file, `--history` found no commit, git failed, a pre-push line was not four fields, or the list was empty. **A refusal is a refusal:** as a hook, 1 and 2 both stop the push; in `run_all.py` it reports like every other check (the owner's ruling: the private check stops a push; the public code reports here).
- **Exclusions**, in `--tree`, `--history` and `--prepush` (every mode that reads this repository's files; `--files` and `--stdin` read what they are given), and covering a file's name as well as its content: exactly the files named in `checks/tests/push_scan/MANIFEST` (one repository-relative path per line; `#` lines and blank lines ignored), the MANIFEST itself included, named in the line; in `--history` each commit is read against the MANIFEST as it was in that commit, so the sample list, the MANIFEST and the first fixture land in one commit, and every later plant with its entry (a file committed before its entry would stay red for good: history is never rewritten); an entry that is not the sample list or a file under `checks/tests/push_scan/` is red (a reviewer hid a word in a fixtures folder; a manifest that may name anything is a hiding place). **A sample word must never enter a commit message, an author line or a file outside those exclusions:** history here is never rewritten, and such a word would turn `--history` red for good; the build lane's brief says so.
- **Header:** how it is fired (the hook, `run_all.py`, by hand), and the failure that earned it: the first private version's proof planted words only where its author expected them, and a separate review found five ways a word could slip past.
- **The sample hook** is the text of a pre-push hook that calls `python3 <path to push_scan.py> --prepush --list <path to the list>`, the two paths written into the hook at install, with a comment saying how a person installs it in their own repository (fill in the two paths, copy into `.git/hooks/pre-push`, make it executable) and that a hook can be skipped with `--no-verify`, so it guards the person's own pushes, and a history scan before publishing is the second layer.

## Self-test (`--selftest`, accepting `--no-log`, exit 0 only when every case gives its expected outcome, ending `selftest: PASS` or `selftest: FAIL`): 15 plants, 2 controls, the foldings (red cases beside the plants, not counted among them), the twin, the unreadable case

With the sample list. **File plants, each red in `--files`, `--tree` and `--prepush`** (committed fixture files, planted into a scratch repository the self-test builds): a word in a file at the tip · in a path name · in another case · in full-width letters · spelled with look-alike letters from the table (a Cyrillic letter and a digit for a letter) · with a zero-width space inside · in a UTF-16 file · in a text file with a stray NUL. **Repository plants, each red in `--prepush` and `--history`** (built as live commits in the scratch repository from fixture text; never committed here): a word in a commit message · in the author email · in the committer line · only in an earlier pushed commit, removed at the tip · in a new branch whose commits sit under a stale remote-tracking ref (the self-test feeds `--prepush` the four-field line git would send, the remote id all zeros) · only in a merge commit's resolution · in an annotated tag's message. **Controls, each green:** a clean first push; a file of near-misses (each sample word with one letter changed). **Foldings and list syntax, each with its fixture:** a soft hyphen, a zero-width joiner and superscript letters inside a word (red); a `w:` word inside a longer word (green) and alone (red); a word that appears only on a `#` line of the list (green). **Twin:** a `--tree` that decoded zero files as text (none tracked, or all binary or excluded) is red; an empty list, `--files` with no file and `--history` with no commit are can't tell. **Unreadable:** a pre-push line that is not four fields is can't tell; a push of a deletion alone is CLEAN and counted. **Read as text or not:** a file with a stray NUL and a text extension (decoded, red); a text-extension file that decodes no way, holding a sample word in Latin-1 (read with replacement and as Latin-1, red, counted in the line), and the same with a stray NUL at an even byte length (red, not read as UTF-16 alone); a binary file with no text extension (counted, not scanned, green); a `.txt` file in UTF-16 with no mark, big-endian (red); a link whose target name holds a word (red); a hit beside an unreadable file (exit 1). Every scratch repository is made with git's global and system settings off, the self-test's own identity set in the command and its branch named at init (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `-c user.name -c user.email`, `init -b`), so a fresh container with no identity, and a machine with signing or a hooks path configured, run it the same. The sample words are strings of letters that appear nowhere in the tree and that no one would write (never a word like *fixture*), so a later fixture of another lane cannot carry one by accident. Then the sample hook itself: installed in a scratch clone with a scratch remote, a push carrying a sample word is refused and a clean push goes through (the proof that the hook text, not only the scanner, works). Prints fixture text only.

## Done when

- The self-test passes as above (fifteen plants: the private check proves fourteen, and matching that count is no reason to leave a read unproven, the owner's ruling); `--tree` is green on the committed tree in the guard's line, naming its exclusions; twin and unreadable cases read can't tell.
- A reviewer's own plant, of a kind in the list above, fires; one outside the foldings (a word spelled with spaces) passes, and the header already says so.
- `--history` on a scratch repository with a word planted in a removed file finds it; on this repository, with the sample list, it is green.
