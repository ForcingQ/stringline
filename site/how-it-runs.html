How it runs

How a working session opens and closes, and what waits for the owner's word, is OPEN-PROTOCOL.md. Each decision and its reason is DECISIONS.md. Those two files are the one text of how the work runs; this room points at them and does not copy them.

The words below are the ones the record uses without stopping to explain them.

the checker

The first tool. It compares each quote of a person's words against what that person typed, and says exact, corrected, absent or can't check.

the finished list

The numbered list a session or lane writes before work starts: what will be true when it is done, and how each line is proven, by a command, by the owner's words, or by someone else looking.

lane

One AI agent session with one aim and its own finished list, run beside other lanes. Anything it finds outside its aim gets a home elsewhere and is not pursued there.

measure, never remember

A session reads the actual state of the files and the repository before stating it, rather than trusting what an earlier session said.

the one gotcha

The single thing most likely to bite a first user of a tool, stated on its card.

a planted fault

A fault put deliberately where a real one would arrive, to show that a check fires on it. A check is not trusted until it has.

The earlier work this recreates is not shown. That it mirrors that work is the owner's claim, dated. What you can check: whether each tool fires on its planted fault, and what its run log shows.
