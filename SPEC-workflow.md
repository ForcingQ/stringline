# SPEC · the workflow: every test and every planted fault, on every push

**Ground truth.** The spec's binding decision says one workflow fires everything, and the guard spec says what it fires; the claim "every test, every planted fault, every track" had no done-when of its own and no twin, so a workflow that ran nothing would read green. The owner's ruling: a workflow runs every test and planted fault on every push. Automation is enabled on the repository (measured at the third session).

**In.** `.github/workflows/checks.yml`; a test runner `checks/run_tests.py` that finds every self-test in the tree and runs it; the proof that the tests leave the tree as they found it. **Out.** Any step that merges, pushes, releases or writes to the repository; any secret. **Deferred.** A badge; running on a schedule.

## The runner: `checks/run_tests.py`

- **Finds its tests; never a hand-kept list.** A test is a tracked file (`git ls-files`) at exactly one of these places, whose text holds the flag `--selftest`: `checks/<name>.py`, `tools/<name>.py`, `tools/<id>/<main>.py` (one level inside a tool folder) and `render.py` at the root; nothing under any `tests/` folder is a test. Every test is run as `python3 <file> --selftest --no-log` from the repository root, with `PYTHONDONTWRITEBYTECODE=1` in its environment (a check, the renderer and the log module accept `--no-log` and ignore it; the binding decision gives the flag to every self-test, and [SPEC-corpus.md](SPEC-corpus.md) and [SPEC-run-log.md](SPEC-run-log.md) say so for theirs). *Why derived:* a list in the workflow and a test in the tree are two hand-kept copies, and the drift is a test nothing runs, the most repeated gap in the originals. The runner's own file is included (its self-test is below).
- **Partial discovery is red.** Every `checks/tests/<name>/` folder must have a discovered `checks/<name>.py` beside it and every `tools/<id>/tests/` a discovered main file; a fixtures folder with no test found for it is red, naming the folder. *Why:* the runner always finds itself, so zero tests can never fire on the real tree; the blindness that can is a test the pattern missed.
- **One line per test** and the rule that decides it, read from standard output's last line and the exit code: `PASS · <file>` on exit 0; `FAIL · <file> · <last line>` on exit 1; `CAN'T TELL · <file> · <why>` on exit 2 or any other code, on a crash (a non-zero exit whose standard error ends in a Python traceback; exit 0 is never a crash, so a handled error a test prints is not one), a timeout at 300 seconds, empty standard output, or a last line of the form `selftest: PASS` or `selftest: FAIL` that disagrees with the exit code. **Every self-test ends with that line** (the lanes' shared rule); a last line of another shape is read by the exit code alone and said. Then `ran n · passed n · failed n · can't tell n`. Exit 1 if any failed, a fixtures folder has no test, or the tree changed, else 2 if any can't tell, else 0. **Twin:** zero tests found is red; it fires in the self-test's scratch tree, as the previous line says it cannot on the real one.
- **Leaves the tree as it found it, and proves it:** before and after the run the runner takes `git status --porcelain --ignored --untracked-files=all` for the whole tree (ignored files included, so a hook fixture's state folder is seen; `__pycache__/` paths left out of the comparison and said in the line, since an import may write them whatever a test does); any difference is red, naming each path (a self-test that logged a row, a renderer that wrote in place, a hook fixture that left its state behind). A tree already dirty before the run is said in the line (*tree dirty before the run: n paths*), and a write into one of those paths is not proven by hand; in the workflow the tree is clean. *Why here:* the workflow's read-only token guards the remote, not the runner's own tree; this proves every self-test honours `--no-log` and writes only to scratch. Self-tests print fixture text only, so the runner's output carries no real material.
- **Its own self-test** (`--selftest`, fixtures in `checks/tests/run_tests/`, run in a scratch tree it builds): a passing test, a failing one, a crashing one, a silent one, one that exits 0 with the last line `selftest: FAIL` (can't tell), one that writes a file and one that writes only into an ignored folder (each red by the tree check), one that crashes with exit 1 (can't tell), a fixtures folder with no test beside it (red), a scratch tree with zero tests (twin). Prints fixture text only.

## The workflow: `.github/workflows/checks.yml`

- **On** every `push` and every `pull_request`. **Permissions:** `contents: read`, nothing else. **Steps:** on the standard Linux runner, check out with the standard checkout action at a major version the lane pins and names in the file, with `fetch-depth: 0` (check 1 reads history; a shallow clone is can't tell); set up Python 3.11 with the standard Python action, pinned the same way; `python3 checks/run_all.py`; `python3 checks/run_tests.py`; `python3 tools/your-words/your_words.py --no-log` (the quote checker as a report). **Every step carries `if: ${{ !cancelled() }}`**, so a red step does not skip the ones after it (and a cancelled run does not go on) and the lines of all three are in every run (*why:* by default a failed step skips the rest, and "the lines say which" would be false). Each step's exit code fails the job, so the job is red on any red and on any can't tell (both are non-zero). On a branch where a tool does not exist yet, its step is can't tell and the job is red until that lane's merge: the merge order in [MAP.md](MAP.md) is what turns it green, and a lane merges main (never rebases) to pick up the others' work. The same three commands run by hand give the same lines.
- **The workflow carries no test list of its own**; adding a self-test to the tree adds it to the run with no edit here. What a reviewer can plant against the workflow file is a step removed, which is why the done-when below runs the three commands by name.
- **Header,** as a comment at the top of the file: how it is fired, the failure that earned it (a correct check nothing runs), and that it writes nothing back.

## Done when

- The runner's self-test passes; on the committed tree it finds every self-test the other spec parts name (the four checks and the scanner, `run_all`, `runlog`, `render`, the quote checker, the extractor, the done-list checker, itself), runs each, and exits 0.
- The workflow file names the three commands, `fetch-depth: 0`, `contents: read` and `!cancelled()`; a run on a pushed branch shows run_all's lines, the runner's summary and the quote checker's summary, quoted in the lane's reports with the run's address.
- Red shown once, in one gated act: a pushed fixture fault (a plant that turns one self-test red) makes the run red, then a renamed check makes run_all's line can't tell and the run red, each reverted, all four commits recorded.
- A fresh clone with Python 3.11 and git runs the three commands with the same results as the workflow.
