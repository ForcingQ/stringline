# SPEC · the first tool: a checker for quotes of a person's own typed words

**Ground truth.** The owner keeps his words verbatim in files and has an auditor match them to what he typed; the one quote checker in his practice reports found, found elsewhere, or not found, and files what it could not check as not found, the collapse the intent forbids. This repository already carries real work for it: INTENT.md and LEARNED.md quote him, INTENT says the quotes are "with my typing corrected" and uses … for words left out, and [WORDS.txt](WORDS.txt) holds the typed messages those quotes come from, exactly as typed. Measured this session, and executed by a reviewer on copies: eight quotes, three exact, five corrected, none absent; the set grows as pages are added, so the counts a lane checks against are measured by the watch at that lane's open. Each block in WORDS.txt is the quoted span as the owner typed it, like the intent's lines, never the message around it (his ruling).

**In.** `tools/your-words/your_words.py`: read quotes from markdown, compare each against typed messages, give one of four outcomes, log the run. **Out of this part.** The extractor that pulls typed messages out of a session record: placed on [MAP.md](MAP.md) in the same lane after the checker, specified at a further session; it writes the same plain-text shape. **Deferred.** Any outcome beyond the four.

## Inputs

- **Typed messages:** a UTF-8 text file; a message is a block of one or more non-blank lines; blocks are separated by blank lines (a line is blank when it holds only white space, a carriage return included); nothing else in the file. Default `WORDS.txt`. *Why plain text:* the tool stands alone, on any machine, with no session-record format to price; the feeder produces this shape later.
- **Quote sources:** markdown files, default every `*.md` in the repository's top folder. After removing inline code (between backticks) and fenced code blocks, a quote is the shortest text on one line between an opening star-quote and a closing quote-star; two on one line are two quotes. `…` inside a quote marks words left out. A quote that itself contains a backtick is can't check (quotes hold prose, never code; a reviewer hid a *not* in a code span inside one). *Why remove code:* a page that explains the quote marks would otherwise read as quoting them (a reviewer executed this and the spec's own page read as a false catch).

## Outcomes, one per quote

A quote's parts (split at …; an empty part at either end is dropped, and that … covers whatever words lie beyond the quote in the message) must appear in order within one message; the gap each … covers is measured in typed words. **Exact is judged on the raw text**, curly quotes and capitals included. **Folding applies to corrected only:** case, runs of white space, curly to straight quote marks and apostrophes, and punctuation at a word's edges. The one-in-eight budget counts the quote's words.
- **exact**: each part appears, character for character, in one message, in order, and every … covers three or more typed words.
- **corrected**: not exact, but each part aligns in order to a span of one message where, over the whole quote, at most one word in eight differs (rounded up, so a short quote allows one), each differing word is a replacement within two letter edits (a swap of two neighbouring letters counts as one) or a dropped typed word (at most two drops in total; **a word the quote adds that the message lacks is never corrected**: an insertion is a misquote, not a typing fix), and the first and last word of every part match the typed word within two letter edits. An … that covers fewer than three typed words, or none, reads corrected and names the words it skipped (*… marks nothing* when none). Differences erased by folding (case, spacing, punctuation) are still named from the raw text. A fixture one notch looser, sixteen words with four replaced, must read absent.
- **absent**: no message holds the quote, exact or corrected. Also absent, whatever the edit count or the gap: a replaced, inserted, dropped or **…-skipped** word that is a negation (*not, no, never, none, nor*, or ends in *n't* with or without its apostrophe: *dont, cant, wont*). This is a catch.
- **can't check**: the typed-messages file is missing, unreadable, not UTF-8, or holds no message; no quote was found across all the source files; a source file is unreadable; or the quote is marked spoken (a `(spoken)` tag after the closing mark). Reported with the reason; never folded into absent.

When a quote matches several messages, exact outranks corrected, then the earliest message; the line reports the chosen one and how many messages matched. **Every exact and corrected line also shows up to three typed words before and after the matched span**, so a reader sees what the quote cut (*I do not try and* before *claim that I am experienced…*). *Why these rules:* a typo, a dropped word, spacing and a capital are what "typing corrected" means here; an ellipsis that skips one word, a changed edge word and a flipped negation are how a quote is turned into a misquote, and a reviewer built each of them against the first draft. **Not proven:** a within-two-edits replacement that changes meaning (*strong* to *wrong*, *learning* to *earning*) reads corrected; a verbatim fragment cut from a negated sentence reads exact, with the cut words shown beside it; an … that skips three or more words with no negation among them reads exact. The tool checks the words, not the meaning; the line shows the change and the surroundings, and reading them is the person's act.

## Output and exit

One line per quote: `OUTCOME · file:line · the quote's first words… · message n · what differs or why not`. Then a summary: `exact: n · corrected: n · absent: n · can't check: n`, then what was read, what was compared against, what could not be seen. Exit 0 when nothing is absent or unchecked, 1 when any quote is absent (even if others could not be checked), 2 when none is absent but some could not be checked. **The exit is a report: nothing in this repository stops on it, and "can't check" never stops work** (the owner's ruling). `--help` prints what it compares against and what it cannot see.

## Fired by, run log, self-test

- **By hand:** `python3 tools/your-words/your_words.py`, a real run, one `real` row ([SPEC-run-log.md](SPEC-run-log.md)): `read` the source files, `compared_against` the typed-messages file, `outcomes` the four counts, `caught` one line per absent quote. With `--planted "<what, by whom>"` the row is planted and carries the note. **By the workflow:** the same run as a report, `--no-log`, no row.
- `--selftest` runs fixtures in `tools/your-words/tests/`: one quote per outcome, a clean control, the one-notch-looser quote (sixteen words, four replaced), an … splice that skips a negation, a flipped negation, a dropped *dont*, an inserted word, the changed edge word (each must read absent), an … that skips one plain word (corrected, naming it), a quote holding a backtick (can't check), the zero-quotes twin, a typed file of blank lines, a non-UTF-8 typed file; prints fixture text only; writes one `planted` row; exits 0 only when every fixture gives its expected outcome.
- **Header:** how it is fired, and the failure that earned it: a checker that filed what it could not check as not found.

## Done when

- The self-test passes; a reviewer's own plant (a quote changed by one word, run with the plant flag) reads corrected and leaves a planted row; one changed by a sentence, one spliced with … over a negation, one with an added word, and one with a flipped negation each read absent.
- The first real run reports every quote on the top-level pages as exact or corrected with the counts the watch measured at the lane's open (eight quotes, three exact, five corrected, at this writing), names each correction, and leaves one real row; `caught_line` for its card reads *1 real run, nothing caught yet*.
- With WORDS.txt removed and the plant flag given, the run says can't check, exits 2, and leaves a planted row whose `could_not` names the file.
- The tool runs in a fresh container holding only Python 3.11 and git, from a clone of this repository, and the run is recorded in the build log.
