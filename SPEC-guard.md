# SPEC · the guard: five checks that run on every change

**Ground truth.** One earlier manual of the owner's runs three checks in its build: that the manual is not behind its code (a stamp and the commits since), that every card points at a heading that exists, and a strip of notes kept inside the source. Each is its own step; each carries a twin that fails if the check goes blind; proof that each fires lives in commit messages. The private-word check exists here already, in the private folder, refusing a push on 16 cases (14 planted words, 2 clean controls). This spec recreates the first two for a set of small tools, adds two new ones, ships a public copy of the third, and keeps every planted fault in the repository.

**In.** Five checks, how each is fired, its twin, its fixture, what it does not prove. **Out.** Anything that stops work besides the push check (the owner's ruling). **Deferred.** The notes check (nothing to strip here); checks writing the run log.

## Fired by

`.github/workflows/checks.yml` runs `python3 checks/run_all.py` on every push and pull request, with full history fetched (check 1 needs it), then every self-test, then the quote checker as a report. The same commands run by hand. `run_all.py` runs a **fixed list of five**; a check that is missing, crashes, or prints nothing is CAN'T TELL, never green. Each check prints one line, `GREEN · read <n> <things> · against <what>`, `RED: <file or card>: <what>` or `CAN'T TELL: <what it could not see>`, and exits 0, 1 or 2; when a check's printed state and its exit code disagree, `run_all.py` reads it as CAN'T TELL. Every check reads exit codes and standard error of every command it runs, never standard output alone. `run_all.py` exits 1 if any line is red, else 2 if any is can't tell, else 0. *Why red first:* a red is a known fault with a known fix; a can't tell is a blind spot to look at; both are non-zero, and the lines show both. **These report; nothing merges or refuses on them until the owner rules otherwise per check.** The pre-push hook that refuses private words stays private and local, as it is.

## The checks: `checks/<name>.py`, fixtures in `checks/tests/<name>/`

1. **Currency.** For each `released` card: the stamp must be a full 40-character commit id known to the repository **and an ancestor of the current commit** (`git merge-base --is-ancestor`; a branch name, `HEAD`, an unknown id or a commit from an unmerged branch is can't tell, naming the card; a reviewer showed a symbolic stamp, and a stamp from a lane never merged, each stay green forever); `files` must be non-empty and every path must be listed by `git ls-files` (else red, naming the card: the prescribed log command alone prints nothing for a missing path, the same as green); then `git log <stamp>..HEAD -- <files>`, any commit red, naming the card and the commit. Can't tell when `git rev-parse --is-shallow-repository` is true, or git exits non-zero. Twin: a `manual/` folder with no cards is red; a missing `manual/` folder is can't tell (as for check 2); zero released with n building is green, saying *0 released, n building*, so the building phase is neither blind nor permanently red. A warning on standard error with exit 0 is can't tell, naming the warning. *Not proven:* that the card is right; only that someone re-read it after the last change. *Needs:* merges that never rewrite history ([SPEC.md](SPEC.md)).
2. **Resolution.** Over tracked paths only (`git ls-files`), so a link resolves only to a tracked file (a clone must see it): every `#term:` link and every path (relative to the repository root) in any record resolves; every released card's `files` exist; every tool folder (a folder directly under `tools/` holding a `.py` file, `tests` and `__pycache__` excepted) has a card and every card a folder; every record has every key its kind requires and none outside its list, and its `id` equals its file name. Also, for released cards: `files` equals what `python3 tools/<id>/<id with underscores>.py --files` prints, and `earned_by` what `--earned-by` prints (two hand-kept copies, so one check compares them); for building cards the comparison is skipped and counted in the line. Red names the record and the target. Twin: a `manual/` folder that exists with zero records, or a `tools/` folder with tools and no cards, is red; a missing `manual/` folder is can't tell (a lane building the checks before the corpus exists sees can't tell, not red).
3. **Derived readers.** Built with the renderer (lane A; [SPEC-corpus.md](SPEC-corpus.md)): `render.py --out <scratch>`, run from the repository root, equals the **working** `site/`, README.md and CLAUDE.md byte for byte (the working files, so a hand edit reads red before it is committed). Red names the file and the first differing line; a renderer that crashes is can't tell. Twin: an empty render or an empty page is red. Python's ignored cache folder is the one thing a check may leave behind. *Not proven:* that the prose is right.
4. **One screen.** Every `*.md` in the top folder and every record under `manual/`, at every depth (`manual/**/*.toml`), is 60 source lines or fewer, a line being a newline-terminated line plus one for an unterminated last line. Red names the file and its count. Twin: zero files found is red. Code files and run rows are not read, and the line says so. *Not proven:* how many screen rows a page takes when its long lines wrap; the unit is source lines so the check reads the same everywhere.
5. **Private words, public copy.** `checks/private_words.py` with `checks/private-words.sample.txt` scans every tracked file and the current commit message for the sample list: a word in a file, in a message, in an author line, in another case, spelled with look-alike letters (a table of common substitutions, folded before matching); an unreadable file is can't tell. It skips exactly the files named in `checks/tests/private_words/MANIFEST` (its own list file and each plant), by full path (a name-based or folder-wide exclusion would open a hiding place; a reviewer hid a word in the fixtures folder), and names them in its line. Files with a text extension (`.md .txt .toml .py .yml .json .html`) are always decoded, and one that fails to decode is can't tell (a UTF-16 page, a page with a stray NUL); other files git treats as binary are not scanned and are counted by name. The look-alike table is hand-kept and small; a disguise outside it passes, and the header says so. *What it does not cover*, in its header: tag messages, merge commits, earlier commits, pushes; those are the private pre-push check's, which reads everything git sends and stays local. *Why a copy:* the mechanism is shown in public and runs on this repository with a harmless list; the owner's list cannot be published. It is a check, not a tool: it has no card and no log.

**Every check** states in its header: what it compares, how it is fired, the failure that earned it, its twin, and what it does not prove. **Every check's fixtures** are committed and run by its self-test (`python3 checks/<name>.py --selftest`): each plant red, the clean control green, the blind case red, the unreadable case can't tell. Self-tests print fixture text only.

## Done when

- `python3 checks/run_all.py` on the committed tree prints five lines and exits 0 (green on itself); with one check file renamed away it prints CAN'T TELL for that line and exits 2.
- Each self-test runs its committed plants: every plant red, every control green, every twin red, every can't-tell case exit 2; a reviewer plants one fault of their own per check, with the plant flag where a tool is involved, and it fires.
- The workflow runs on a push to a branch and shows the lines; a pushed fixture fault turns it red (shown once, then reverted, both commits in the record).
- A shallow clone makes check 1 say can't tell, not green.
