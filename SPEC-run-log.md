# SPEC · the run log: every row says planted or real

**Ground truth.** The owner's instruments keep logs, and no log tells a planted test run from a real one; proof that a check fires lives in commit messages and handoff notes, outside the artifact (read at the second session). So "has this ever caught something real?" cannot be answered from any original. This build answers it by reading its log.

**In.** The log's location, shape and writer; the rule that separates planted from real; the derivation the card uses. **Out.** Checks writing to it (see [MAP.md](MAP.md), deferred). **Deferred.** Any summary page beyond the card's line.

## Shape

- **Folder `runs/`, one file per run**, JSON, one key per line, named `<UTC time, YYYYMMDDTHHMMSS.ffffffZ>_<tool id>_<kind>.json` (underscores separate; tool ids carry no underscore). *Why:* one file per run keeps planted and real runs apart by name as well as by field, lets a reader count by listing the folder, and the microseconds keep two runs in one second apart (a reviewer lost one of two same-second rows under a whole-second name). The folder is committed: the log is public record. The writer creates the folder when it is missing. Default location: `runs/` under the repository root (`git rev-parse --show-toplevel`), or under the working folder when there is no repository; the tool prints where it wrote. `read` and `compared_against` paths are relative to that root. When the name and the `kind` or `tool` field disagree, the row is can't tell, never read as real. Files that are not `.json` are ignored; a `.json` whose name does not parse is can't tell.
- **Fields, all required:** `tool` (the card's id) · `started` (UTC, ISO 8601; rows are ordered by this field, not by name) · `kind`, exactly `planted` or `real` · `planted_by`: `selftest`, or the note a person gave with the plant flag; empty when real · `invoked_by`: `selftest` or `person` · `read` (what the run read: paths relative to the repository, or `fixture`) · `compared_against` (same) · `outcomes` (a map of outcome name to count, the tool's own vocabulary) · `caught` (array of one-line strings; empty when nothing was caught) · `could_not` (array of one-line strings: what it could not see) · `tool_version` (the latest commit touching the tool's own files; `<id>+dirty` when they have uncommitted changes; `uncommitted` when none has been committed; `no git` when git is unavailable or the folder is not a repository). `could_not` holds what this run could not see, never the tool's standing limits, which belong in `--help`. Dates are UTC.
- **Planted or real is set by the invoker, never by paths.** A self-test writes one planted row (`planted_by = "selftest"`) and nothing else. A person's run is real unless they pass `--planted "<what and by whom>"`, which writes a planted row carrying that note. A reviewer who plants a fault among real files uses that flag; a forgotten flag logs a plant as real, which is accepted and not enforced, since nothing but the person knows. *Why:* this is the field the field exists for, and a fault planted where it would really arrive must still never count as a catch.
- **A row without `kind`, or with another value, is refused by every reader as can't tell**, never read as real.
- **`caught` means a finding a person would act on**, as each tool's spec defines it. A planted row's `caught` is never read by the card.
- **Workflow runs write no rows.** A run in the workflow reports and exits; only a person's run, or a self-test a person runs, leaves a row. *Why:* a workflow cannot commit, so a row it wrote would never reach the folder; the same reason puts `--no-log` on every self-test and tool the workflow runs.

## Writer and reader: `tools/runlog.py`

- `write(tool, files, kind, planted_by, invoked_by, read, compared_against, outcomes, caught, could_not, folder=None)` (the folder defaults to `runs/` under the current working directory; a self-test passes a temporary folder and the tool id `fixture-tool`, which no card may ever carry) fills `started` and `tool_version` (from `files`, the tool's own paths, passed by the tool; the module never reads the corpus), refuses a `kind` outside the two values, a planted row with an empty `planted_by`, **a real row whose `invoked_by` is `selftest`**, and **a real row whose `read` or `compared_against` names `fixture` or any path under a `tests/` folder** (fixtures are never real material; a reviewer's self-test ran the tool's own command as a person and the card showed the plant as a catch), writes the file and returns its path. The module's own self-test uses the temporary folder and the id `fixture-tool`; a tool's self-test writes its one planted row to the real folder.
- `rows(tool)` returns the folder's rows for a tool, newest first by `started`, with malformed files (not JSON, no `kind`, name and field disagreeing) listed separately as can't tell; a missing folder is *no rows*.
- `caught_line(tool)` gives the card's sentence ([SPEC-card.md](SPEC-card.md)) from `rows`: *no real run yet* when no real row is readable, *1 real run, nothing caught yet* or *n real runs, nothing caught yet*, else the caught lines (date, then the line; newest first; at most ten, then *and n more*); whenever a real row has a non-empty `could_not` the sentence adds *· 1 run could not see everything* or *· n runs could not see everything*, and whenever unreadable files exist it adds *· 1 run file could not be read* or *· n run files could not be read*, so a blind read never shows as a clean one (a reviewer showed a run with its words file missing reading as *nothing caught yet*). *Why here:* the renderer must not keep a second reader of the log.
- It is the first thing lane C builds and merges, before the checker; lane A then imports it rather than copying it. Lane B needs nothing from it.

## Done when

- The writer's self-test, in a temporary folder under the fixture tool id, writes a planted and a real row; refuses `kind = "test"`, a planted row with no `planted_by`, and a real row from `invoked_by = "selftest"`, each with a named error; two writes in one second leave two files.
- The reader returns rows newest first by `started`, and lists a file with no `kind`, a file that is not JSON, and a file whose name says `real` but whose field says `planted`, as can't tell without raising; a missing folder gives no rows.
- `caught_line` gives each of its sentences from fixture rows, *no real run yet* on an empty folder (the blind twin), and the *could not be read* tail when a malformed file sits beside a good one.
- The first tool's self-test leaves exactly one planted row per run; its first real run leaves one real row naming `WORDS.txt` under `compared_against`; a `--planted` run leaves a planted row carrying the note.
