# Decisions

Each decision, dated, with its reason. Newest last. What each session did is in [BUILD-LOG.md](BUILD-LOG.md).

## 2026-10-07 · the first working session (the founding)

1. **The intent comes first, and alone.** The repository's first commit is [INTENT.md](INTENT.md) and nothing else, exactly the text the owner approved. *Why:* everything after it is judged against it, so it has to exist before anything it would judge.
2. **The name is stringline.** *Why:* the owner's choice.
3. **The record is kept in two folders.** The working notes, the owner's words and review reports stay in a private folder. This repository carries a build log written for strangers, which is checked against the private notes in both directions. *Why:* what is shown is written for the reader, and the check keeps the public account from dropping a decision or a mistake.
4. **A check, not a promise, keeps private words out.** A local pre-push check scans every file, commit message, author line and tag being pushed against a private word list and refuses the push on any hit. It was shown to refuse planted words in a scratch copy before the first real push. *Why:* private stays private because a check refuses the push, not because a sentence says so.
5. **Both GitHub repositories, this one and its private sibling, are private** until the owner makes this one public. *Why:* the owner decides when it is ready to be seen.
6. **Commits carry a GitHub no-reply address**, an address GitHub provides so that the author's real email is not published. *Why:* no private email address enters the public history.
7. **No AI agents run inside the product yet, so none are designed yet.** In the way I build, designing the agents a product ships with is its own step, with its own document. That step waits until this build ships an agent. *Why:* there is nothing yet for that step to work on, and writing its document early would be a document about nothing.
8. **An earlier tool of the owner's, kept in its own private repository, stays private and outside this build.** Whether it is ever brought in or made public is not decided. *Why:* the owner paused it before this build began. The intent lists it under "not decided, on purpose".
9. **Nothing in a working session contacts anyone.** *Why:* anything sent to a person is the owner's own act.

## 2026-10-07 · the second working session (seeing and naming)

10. **The public log carries the build; upkeep stays private and is counted.** Every decision and every wrong turn about the build itself gets a line in the public log. Upkeep of the owner's other work (keeping shared notes tidy, the state of other work, the lists and logs he keeps for himself) is kept private, and each session's entry says in one line how many such items were kept private and why. The reader that checks each close confirms every private item is either in the log or in that count. The founding entry was written before this rule and stands as written. *Why:* publishing a line for every decision pulled the owner's workspace upkeep into a log meant for a stranger, which is what the owner learned from the founding ([LEARNED.md](LEARNED.md)). The count keeps the two-way check honest without the clutter.
11. **Taking any word off the private word list waits for the owner's word.** *Why:* a word taken off is a word the push check stops refusing. The founding took one off so that a pointer in these files could pass; that call should have been the owner's.
12. **The README stays signed with the owner's name.** *Why:* the owner's ruling; the founding had left it open for him.
13. **Questions for the owner come as one line; everything else the session decides.** Anything that waits for his word comes as what is recommended, why, and what happens on his yes. Everything else is decided, recorded with its reason, and told to him after. *Why:* the owner's ruling: recommendations, not menus. A question that reading or measuring can answer is not his to answer.
14. **The intent stays as it is for now.** Two phrases a cold reader could not follow get plain words from this session, and the owner rules any added line at the next one. *Why:* the intent changes only by his word.
15. **Each session's log entry is its own file, beside a one-screen front page.** [BUILD-LOG.md](BUILD-LOG.md) now holds the rules and the list of entries; the founding entry moved, byte for byte, to its own file. *Why:* every file here fits on one screen, and a second entry would have pushed the log past it. The entries sit in the top folder, not a subfolder, because the founding entry's links were written from there and must keep working without editing it.
16. **The first tool is a quote checker for the owner's own words; the runner-up is a done-list checker.** The quote checker compares each quote of a person against that person's typed messages and gives one of four outcomes: exact, corrected, absent, or can't check. Pulling the typed messages out of a session's record comes after it. *Why:* the intent names this tool first. The one quote checker that exists in the owner's private work reports what it could not check as missing, the very collapse this build exists to refuse, so the first tool shows his practice improving its own instrument in the open. The runner-up's original is the most portable, and its founding mistake is already in this log.
