## What this is

*"I am building a public tool to mirror my designs from private work to showcase both a tool, a build told through the sessions and the code, and a design/output that the reader can engage with through a clean, interactive and well structured environment. The repo tells the story, the tool lets them engage in it."*

I rebuild in the open, from scratch, designs I first proved in private work.

Three things, in one repository:

- **A tool.** Small instruments recreated from my own practice, starting with one that carries my words verbatim. Where a tool checks what an agent said, it says what it looked at and what it compared against, and says can't tell, never clean, when it cannot see. No check is trusted until it has been shown it can fire on the fault it guards against, planted where that fault would really arrive.
- **A build, told through its sessions and its code.** Built in public from its first commit, the way I build: intent before anything, direction before code, the sequence set by what depends on what, agents doing the work under written instructions, review of every spec by a reader that did not write it, and a public log (the record) of each decision and each wrong turn caught, dated.
- **A manual the reader walks.** A clean, interactive, well-structured surface, built the way I build operating manuals for products I build: one source held as data; one card per released tool, saying what it is, the first thing to do, the one gotcha and what it has caught; a walk through the record; and how the work runs. The same source will be the README and the instructions for any agent working here, checked against the code on every change, so it cannot quietly fall behind.

*"The builder framework and mindset of how I work, creating a tool that is a product of it as well as a guidebook through it"*

That is, the step-by-step method I build with (see what is true, name it, map what depends on what, order it, specify it, build, test, learn), and the habits of mind behind it.

## Why

*"Showing code is one thing, showing how we think and operate is another."* The way the work gets made is what I have to show, so the record of making it is the exhibit, and the manual is how a reader walks it.

*"I do not try and claim that I am experienced in the code I write, I do claim that I am strong in working with AI, guiding it, learning it, exploring solutions, creativity, building to close gaps, create new ways, explore ideas from many different approaches, open to change, always learning …"* This build shows that, by doing it where it can be read.

The instruments in my own practice exist because agents told me things about my environment that I could not trust. I built the instrument instead of trusting harder. Its first tools are that act, made so someone else can hold them.

It is built to stand on its own.

## Where it is going

1. A stranger can follow the record and walk the manual without translating anything. No private vocabulary travels, and a check on this repository looks for it before anything is pushed.
2. The record shows how I direct, test and review the work: a call made, a reason given, a wrong turn caught, and what changed because of it.
3. The instruments catch something real in a project of mine they are run on, not only the faults planted to prove them.
4. Someone who is not me installs a tool from it on a clean machine, and it works there.
5. What I learn building it is recorded as I learn it, in my own words, the session it lands.

## How it runs

*"We build things right, not fast. The time it takes for me to produce is mine to own …"*

*"We are mission driven, focused and we run clean."* Every working session opens with a list that says when it is finished. Work runs in lanes: separate agent sessions, each with one aim and its own such list. Anything found that is not on the list gets a home outside the lane and is not pursued in the session that found it. A reader that did not do the work checks each session's record before it is relied on, and what it finds is added to the record, dated, beside what it corrects. A reviewer writes its rules before it reads the builder's account, and plants its own faults rather than running the builder's tests.

Every manual page one screen. Structure is built when the work first needs it.

## What this does not claim

Production use. Users. That any tool is more than what its self-test and its run log show. That a clean run means the work is good: the instruments guard claims, and whether the work is wanted is my call. That I wrote the code by hand: Claude Code writes the implementation under my direction and review, and the record says which is which. That this is the private work it mirrors: everything here is recreated, and nothing from a client or a private build is in it.

## Not decided, on purpose

Which tools come after the first. Which moments the first instruments cover. Whether an instrument only reports, or may stop the work. Whether per-session cost logging is in the first release. Whether an earlier tool of mine is one they are run on. How open the session records are. Who else uses it. Whether any one reader's answer counts as success. Whether the manual ever answers questions itself.
